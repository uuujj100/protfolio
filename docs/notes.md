# 技术笔记

写这个文件的目的：把两个 demo 里那些「看起来能跑，但不知道为什么这么写」的地方记下来。
每一条都对应一段真实踩过的坑。

---

## 1. 视频首帧卡顿：为什么"整体加载"是错的

播放大文件时，浏览器默认会从文件开头往下下载。如果 `moov`（索引表）在文件尾部，
浏览器必须先跳过整个视频数据才能拿到时长和关键帧位置 —— 这段时间里播放器是黑的。

**三种缓解手段，按收益排序：**

| 手段 | 做法 | 代价 |
| --- | --- | --- |
| 索引前置 | 转码时加 `-movflags +faststart`，把 `moov` 挪到文件头 | 需要重编码一次 |
| 分片预读 | 只预读前若干字节，拿到元数据就开播，后面的按需 Range 请求 | 多一次网络往返 |
| 顺序播放 | 预读结束后按 `buffered` 区间顺序补齐 | 拖动进度条时要重新预读 |

`n7-player.html` 里用的是第三种思路的浏览器实现：`preload="metadata"` 先拿元数据，
播放器自己读 `video.buffered` 判断缓冲区水位。所以状态栏里那行"已缓冲 x / y"
不是装饰，它就是这个策略的观测点。

**关键点**：`buffered` 是一个 `TimeRanges`，可能有多段（用户拖动后会产生断档）。
判断"能不能直接播"要用 `buffered.end(i) >= currentTime`，而不是看总缓冲时长。

## 2. 进度记忆：为什么 key 不能用文件路径

`URL.createObjectURL(file)` 每次调用都会生成一个新的 blob URL，同一个文件刷新页面后
地址就变了。拿它当 key，进度永远对不上。

这里用的是 `文件名 + 字节大小`：

```js
const key = `f:${file.name}:${file.size}`;
```

文件名可能重复，但两个不同文件大小完全相同的概率很低，够用且不需要读文件内容。
远程地址则直接用 URL 本身当 key。

**写入时机**：`pause` / `ended` / 每 5 秒 / `beforeunload` 四个点。
只在 `playing` 时定时写会漏掉"直接关窗口"的情况。

**恢复时机**：必须等 `loadedmetadata` 之后，否则 `duration` 还是 `NaN`，
`currentTime = x` 会被静默丢弃。

## 3. 定位坐标：为什么必须做转换

浏览器 `Geolocation` 返回的是 **WGS84**（GPS 原始坐标）。
国内地图服务（高德、腾讯、百度）用的是 **GCJ02**（"火星坐标"，国家测绘局加密后的坐标系）。
两者在中国境内相差 **300～500 米** —— 直接拿 WGS84 去标地图，会稳定偏到隔壁街区。

`geomock.html` 里实现了 WGS84 → GCJ02 的标准算法：

1. 先判断是否在境外（`outOfChina`），境外不做偏移；
2. 对经纬度做一组正余弦多项式扰动，得到 `dLat` / `dLon`；
3. 用椭球参数 `a = 6378245.0`、`ee = 0.00669342162296594323` 把角度修正回米制。

**验证方法**：拿一个已知点（比如天安门 WGS84 `39.908722, 116.397499`），
转换后应该落在 GCJ02 `39.910092, 116.403694` 附近，误差在几十米内属正常。

百度用的是 BD09，还要在 GCJ02 基础上再做一次转换，这里没做 —— 用不到就不写。

## 4. 定位漂移：为什么不用卡尔曼滤波

连续定位时坐标会抖，原因有三：多径反射、基站/WiFi 定位精度低、以及浏览器自身的节流。

`position.coords.accuracy` 是**半径（米）**，不是百分比。精度 500 意味着可能偏 500 米。
所以第一个判断应该是：`accuracy > 100` 的点直接降权或丢弃，而不是硬画在轨迹上。

这里用的是**移动平均**（窗口 3）：

```js
const avg = seg.reduce((a, p) => a + p.lat, 0) / seg.length;
```

为什么不上卡尔曼滤波：

- 卡尔曼需要运动模型（速度、加速度）和噪声协方差矩阵，参数要靠实测拟合；
- 移动平均一句话能讲清，效果对"走路轨迹"这类低速场景够用；
- 引入滤波会让代码从 20 行变成 200 行，维护成本远大于收益。

**结论**：先看精度半径做数据清洗，再用简单平滑。复杂模型留到真有需求的时候。

## 5. 浏览器定位的三条硬限制

1. **必须 HTTPS 或 localhost**。`file://` 打开会直接拿到 `code 1`。
   GitHub Pages 自带 HTTPS，所以这个 demo 能直接跑。
2. **必须用户手动授权**，且授权结果按源（origin）记忆，换域名要重新授权。
3. **错误码只有三种**，但含义容易混：

| code | 含义 | 常见诱因 |
| --- | --- | --- |
| 1 | PERMISSION_DENIED | 用户点了拒绝；或非安全上下文 |
| 2 | POSITION_UNAVAILABLE | 设备无定位模块；系统定位服务被关 |
| 3 | TIMEOUT | 室内信号弱；`timeout` 设太短 |

把这三个码映射成人话写进 UI，比弹一个 `alert(e.message)` 有用得多。

## 6. 已知边界

- 播放器未做字幕轨道（`<track>`）和画中画（PiP）支持；
- 分片预读目前依赖浏览器原生 `preload` 行为，未手写 `Range` 请求；
- 定位 demo 未接地图底图，只画相对轨迹 —— 接底图需要申请地图服务 key；
- 轨迹平滑窗口固定为 3，未按采样频率自适应。

这些不是"没想到"，是当前用不到。写清楚边界，比假装完备更省事。
